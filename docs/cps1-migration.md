# CPS1 authority and core ownership migration

## Verified source

CPS1 uses Coin-Op Collection at revision `709cab401cd4317a025bf0d90be1dbc568873ba6`, database SHA-256 `44a780e010fac5f00e6af42310ec4ca18720947b72f47d751cc0840e0cb043c1`. Public MRA hashes, sizes, `Capcom CP System Hardware` platform metadata and MRA/RBF references establish the 27-primary, 111-alternative inventory. No filename-only hardware inference is used.

The module remains `capcom-cps1`, database ID `hyp36rmax/MisterFPGA-DownloaderPLUS/capcom-cps1`, at `_Arcade/_Arcade Systems/_CAPCOM CPS1/`. Its source is now Coin-Op; CPS1.5, CPS2 and CPS3 remain JTCORES. No Jotego CPS1 records are mixed into the new view.

## Filters and authorization

The original source filter, full tag dictionary, record tags, effective source URLs and MRA bytes are retained. The current CPS1 records have no source exclusion tag attached; DownloaderPLUS does not invent one. Each of the 138 MRAs includes the original `rom index="37"`, `zip="coinopkey.zip"`, `part name="coinop.key"` reference. The account/device-bound authorization remains Coin-Op's responsibility and is not bypassed or supplied here.

The CPS1 family explicitly preserves source filtering and fails closed if a selected MRA or its required upstream core is excluded. Complete cannot publish such a contributor. Keys, account data, protected bitstreams, game ROMs and BIOS data are not embedded in the derived databases or generated by this project. Hardware testing with a valid authorized account/device remains outstanding.

## Normal Downloader reconciliation

Reviewed [Downloader revision 5d077135](https://github.com/MiSTer-devel/Downloader_MiSTer/tree/5d0771359ae396aaea64453e6791ac87781d78f4). [Database stores](https://github.com/MiSTer-devel/Downloader_MiSTer/blob/5d0771359ae396aaea64453e6791ac87781d78f4/src/downloader/jobs/mix_store_and_db_worker.py) are keyed by the unchanged derived database ID. Changing source authority does not discard the old ownership store.

[Reconciliation candidates](https://github.com/MiSTer-devel/Downloader_MiSTer/blob/5d0771359ae396aaea64453e6791ac87781d78f4/src/downloader/jobs/process_db_index_worker.py) are previously tracked paths absent from the new index. The inspected previous `capcom-cps1` artifact contains 159 such Jotego MRAs, all beneath the existing CPS1 navigation root. Normal cleanup covers both primaries and recursive alternatives. Complete subscribers retire the corresponding old records through their Complete store.

[Removal execution](https://github.com/MiSTer-devel/Downloader_MiSTer/blob/5d0771359ae396aaea64453e6791ac87781d78f4/src/downloader/online_importer.py) protects paths still claimed by any other stored database, including skipped, failed and dormant stores, using case-insensitive ownership checks. Untracked user files are not candidates. Nonempty directories are retained; there is no recursive directory deletion or custom migration script.

Deletion follows the user's existing setting. The normal `AllowDelete.ALL` policy retires obsolete MRAs. `OLD_RBF` permits only obsolete RBF removal; `NONE` removes neither. No setting is overridden. When deletion is disabled, obsolete files can remain and their old store records may be dropped, so enabling deletion later does not guarantee retrospective cleanup. An edited file still tracked by Downloader remains tracked ownership; retirement is not a fresh local hash comparison. No broad deletion command is provided.

Independent JTCORES subscriptions and their standard-location cores are untouched. Other Capcom views retain their identities and authorities.

## Coin-Op Collection cores

The normal Coin-Op subscription already publishes its RBFs in `_Arcade/cores/`. DownloaderPLUS therefore omits those core records and the core folder from the dedicated Coin-Op database, rather than acquiring a second owner at that path. MRAs and recursive alternatives stay under `_Arcade/_Coin-Op Collection/`; external `games/mame` and `games/hbmame` paths are unchanged.

The previous dedicated database tracked 56 nested RBF copies. Their records disappear and are eligible for normal Downloader retirement, subject to deletion settings and other-store claims. The current source's 83 RBF records remain upstream-owned. No new nested or standard core owner is introduced by Coin-Op Collection or CPS1. Existing unrelated family core-ownership exceptions are unchanged.

All Coin-Op views share the refreshed source snapshot. Previously published non-CPS1 payload filenames, hashes and sizes are unchanged; URLs and numeric tag IDs refresh with upstream. Semantic tags are preserved. The dependent TATE collection keeps its counts, with 1941: Counter Attack and Mercs changing authority from JTCORES to Coin-Op. The historical master is unchanged.

## Regression evidence

The pinned public source and MRA evidence fixtures contain metadata only, never cores or keys. Cleanup tests execute the relevant candidate/removal blocks from the pinned upstream Downloader source with temporary files and in-memory ownership stores. They cover tracked obsolete files, untracked user files, case-insensitive other-store claims, deletion-disabled settings and legacy nested RBF retirement. The upstream source fixture retains its original license and is not a production dependency.
